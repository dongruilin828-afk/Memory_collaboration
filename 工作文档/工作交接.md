# “强国之路”项目工作交接

> 最后整理：2026-09-01  
> 面向对象：第一次加入本项目的开发者  
> 一句话定位：这是一个 Windows 本地工具，用浏览器抓取 ChatGPT、DeepSeek、豆包对话，再按需调用 Gemini、SiliconFlow 或 DeepSeek 生成可续接的分层记忆。

这份文档不是产品宣传，而是接手工作的入口。它汇总了本项目历次任务中验证过的做法、失败过的方案、当前发布状态和仍需人工确认的事项。开始改代码前，请先读本文件、`agents.md`、`README.md` 和 `工作文档/经验总结.txt`；若文档与当前代码冲突，以代码、测试和最近一次真实样例为准。

## 1. 接手前先记住的四条规则

1. 未经明确允许，不允许执行 `git commit`。
2. 未经明确允许，不允许创建或切换新分支。
3. 不把浏览器登录资料、API KEY、运行日志、测试产物或私人链接复制到公开位置。
4. 修改必须定点、可验证。先找到根因和所有调用方，再改共享根因或平台专属分支；不要为了修一个样例重写已经跑通的主链。

允许阅读 GitHub 公开内容。删除、覆盖、清理、系统设置修改和联网发送私人数据必须遵守用户授权边界。

## 3. 五分钟跑起来

### 开发环境

在项目根目录运行：

```powershell
uv pip install -r requirements.txt
playwright install chromium
uv run python -m gui.app
```

不要在 `gui` 目录里直接运行 `app.py`；项目使用包导入和集中路径计算，统一从根目录以 `python -m ...` 启动。

常用命令：

```powershell
# 只抓取，不调用总结 API
uv run python -m scripts.parser

# 对已有导出做单文件总结
uv run python -m scripts.summarize_memory "results/export/ChatGPT_含图片.md"

# 离线全量单元测试，不调用真实 API
.\.venv\Scripts\python.exe -m unittest discover -v

# 真实网页抓取回归，不调用总结 API
uv run python -m tests.run_tests

# 对已有测试导出批量生成普通版/详细版/极简版，会调用模型 API
uv run python -m tests.summarize_tests
uv run python -m tests.summarize_tests --include-details
uv run python -m tests.summarize_tests_simple
```

PowerShell 出现 emoji/中文编码异常时，先设置：

```powershell
$env:PYTHONUTF8 = "1"
$env:PYTHONIOENCODING = "utf-8"
```

不要误用系统 Python。曾经出现过测试只跑 20 项并报 `markdownify` 缺失，根因就是命令落到了 `D:\pyD` 的系统 Python，而不是项目 `.venv`。

### GUI 当前能力

- 输入公开分享链接或账号内链接，抓取原文、图片和当前账号有权下载的文档。
- 可选“仅抓取”“普通版”“极简版”“详细版”；普通版和详细版共享同一份结构化结果。
- 可点击“选取文件总结”或拖入文件后直接总结。
- 直接总结只接受 UTF-8 的 `.md`/`.txt`，文件必须非空且不超过 10 MiB；它面向本项目导出的对话格式，不是任意文档阅读器。
- 普通版/详细版完成主题分类后，用户可勾选具体重点主题；未勾选的主题摘要仍完整保留。
- 右上角设置可配置 API KEY、API 回退顺序、运行数据位置和默认结果目录。

主链可以理解为：

```text
链接或导出文件
  → 浏览器采集/本地读取
  → 平台解析为统一 User/AI 消息
```

## 5. 最重要的工程原则

### 5.1 先守住稳定主链

这个项目曾因“顺手完善”导致已有平台直接不能运行，最后只能强制回滚。不要把 DOM 脆弱、路径不好看或代码重复自动等同于“应该大改”。正确顺序是：

1. 用真实失败样例复现。
2. 判断问题属于抓取、解析、资源下载、总结、渲染、缓存还是打包。
3. `rg` 搜索目标函数的所有调用方和同类平台路径。
4. 优先修共同根因；若问题是平台特有结构，则限制在平台分支。
5. 留一个能复现该结构的最小测试。
6. 跑全量离线测试，再按风险做真实页面回归。

“改动少”不等于只给报错位置打补丁；能在共享入口一次解决所有调用方的根因，才是真正的小改动。

### 5.2 成功退出不等于内容正确

历史上 `run_tests` 曾显示全部生成成功，但数学公式用例实际抓到的是 Cloudflare“请稍候/验证成功”页面；也曾出现消息数量正确、图片却挂到错误用户消息的情况。验收至少检查：

- 用户消息数、AI 消息数和严格顺序；
- 第一条、中间关键点、最后一条是否存在；
- 图片/文档数量、可访问性和所属消息；
- 代码围栏、LaTeX、中文、附件名称是否完整；
- 页面按钮、思考过程、favicon 等界面杂音是否混入；
- 总结里的事实、角色、状态、数字是否能回指原文。

### 5.3 旧产物不会自动变好

修改解析或总结代码后，已经生成的桌面 Markdown/JSON 不会自动更新；运行中的 GUI 也仍使用启动时载入的旧代码。测试新版前必须重启 GUI，并重新生成目标产物。

## 6. 浏览器抓取：走过的坑

### 6.1 SPA 不要等 `networkidle`

ChatGPT 等单页应用长期保持网络连接，`wait_until="networkidle"` 容易超时。当前经验是：

- 导航用 `domcontentloaded`；
- 等待平台稳定 DOM；
- 超时要显式记录并允许受控降级；
- 抓取失败必须返回失败，不要以 0 退出码让批处理再空等半小时。

旧版曾在页面超时后正常退出，`run_tests` 随后等待不存在的导出文件 1800 秒，造成“假卡死”。现在应快速失败、有限重试并继续下一项。

### 6.2 虚拟列表必须逐屏采集

ChatGPT 和 DeepSeek 只渲染视口附近消息。单纯把后台视口拉到 `1920×10800` 只能缓解，不能保证完整；真实故障包括顶部少三条、DeepSeek 键 1 未挂载、附件刷新后 16 条缩成 10 条。

稳定做法：

- 从顶部到末尾逐屏采集；
- 首尾边界重复采集；
- 用稳定消息 ID/虚拟键排序、去重；
- 同一消息复采时优先保留正文不退步、图片更多的快照；
- 不能按 HTML 总长度决定“新快照更好”，按钮和工具栏也会让 HTML 变长；
- 附件重载前先冻结完整消息，后续快照只允许补资源，不能删除原消息。

### 6.3 可见窗口、无头和最小化不是一回事

- 人工登录必须用原生正常视口，避免超高 viewport 把登录 UI 挤坏。
- 全量版使用内置 Chromium；轻量版优先系统 Edge，失败后用 Chrome。
- ChatGPT 私有会话在同一登录资料下可能出现“无头空白、可见模式已登录且可读”，所以当前直接使用始终最小化的有界面浏览器；只有最小化窗口仍无法读取时才恢复窗口请求登录。
- 每次站内导航、返回原对话、点击文档卡片后都要再次最小化，避免下载一个文件就弹一次窗口。
- “不登录”表示先复用已有登录态并尽量不打扰用户，不表示绝不使用浏览器。

### 6.4 浏览器清理错误不能抹掉成功结果

Playwright/Node 驱动可能在 `BrowserContext.close()` 时断连，甚至出现证书对象异常。若正文和资源已成功抓取，关闭阶段异常应记录为 `fetch_warning`，不能把已完成任务改判为抓取失败。

## 7. 三个平台的专属经验

### 7.1 ChatGPT

- 长对话依赖虚拟列表逐屏采集；超高窗口不是完整方案。
- 分享页图片和文档不能用“全页资源顺序与消息占位符 zip”。源码资源可能倒序，动态响应顺序也会变化，曾导致两张图互换。应读取线性会话数据，按具体用户消息绑定资源，并保留同一消息多图的顺序。
- ChatGPT 图片端点有时先返回约 600 字节的 JSON，其中才含真正签名下载地址。必须继续下载真实字节并校验文件头；不能把 JSON 直接保存成 PNG，也不能复用旧坏文件。
- 私有附件可能需要逐卡片重新授权；已经从浏览器响应拿到的成功文件应直接复用，不要二次请求制造 403。
- 附件刷新、站内重挂载前先冻结完整消息。为恢复文件卡片可进入空白“新对话”再返回原链接，但不得采集或混入其他历史会话内容。
- 普通正文中的 `report.pdf`、`hashlib.md5`、文件路径不能靠正则猜成附件；只认文件卡片、平台元数据或已下载文件。
- 嵌套 `<pre>` 和双层 Markdown 围栏要做对称清理；不要依赖易变的 `cm-content` 类名。
- 数学节点要在 Markdown 转换前恢复原始 LaTeX，输出 `$...$`/`$$...$$`。
- Cloudflare 验证页不是有效对话。`ChatGPT_含数学公式.md` 当前仍被黄金基线明确排除。

### 7.2 DeepSeek

- 使用 `data-virtual-list-item-key` 排序、去重；只保留最终 AI 回答，排除“已思考”和按钮文本。
- 曾有一个测试是 118 个用户消息 + 118 个 AI 回答。当时有一条纯图片用户消息没有原图地址，但后续 Pottermore 回答存在；正确做法是保留“原图已失效或加载失败”占位，不能直接丢掉该轮。
- 普通网页引用 `.html/.htm` 曾被误判为 20 个文档附件，挤占提示词并让总结只覆盖后半段。只有真实文件卡片/本地文件才是文档，且 DeepSeek 的密集对话小分块策略必须只在 DeepSeek 场景启用。
- 只总结后几十条不一定是抓取问题：可能是模型只为后段生成 `memory_items`，而最终主题又只依赖这些记忆；先检查原消息数、分块覆盖、记忆覆盖和最近上下文，再决定改抓取还是总结。
- 文档内部的英语词汇、旧任务或章节不能独立成为本次对话主题；用户若只是“识别文档”，主题应围绕文档识别，而不是附件内容中的每个话题。
- 历史资源若官方端点对 `p/t/r` 都稳定返回 404，应保留元数据与不可复核状态，停止刷新和猜测。

### 7.3 豆包

- 分享页和 `/chat/` 直链 DOM 不完全相同；直链必须只抓当前会话，不能混入侧栏、历史记录或输入框。
- 长对话图片是逐消息懒加载的。必须把每条消息滚入视口，等待真实图片节点出现；短对话首屏能成功不代表长对话也能成功。
- 空 `data:image/svg+xml` 是懒加载占位，不是正文图片；重复的 `img-z0eKj1` TikTok 小图标也是界面噪声。只过滤确认为空的 SVG 和同消息内重复界面图标，有实际图形的 SVG 与单独有意义图片要保留。
- `Asset cover`、base64 封面和 `doc-canvas-card-fallback` 是文档界面装饰，不是用户图片。
- AI 在线文档是文档画布，不等同于普通附件，要从页面状态保存为本地 Markdown 并回链到对应 AI 消息。
- 用户附件元数据可能在打开 AI 文档之后才晚到。打开 AI 文档后必须重新汇总响应候选；只重扫 HTML 会漏掉迟到的用户 DOCX。
- 判断角色不要只押注一个 CSS 类；分享页与登录直链可能使用不同的合成结构。

## 8. 图片与文档：不要混淆三件事

### 8.1 文件是否存在、是否能被模型分析、来源是谁

这三个状态必须分开：

- 本地文件存在：可以打开、可重新验证。
- 模型分析失败：例如 ConnectError/503，只能说明本次识别失败，不能把本地文件写成“不可访问”。
- 来源角色：用户上传、AI 回答、用户/AI 混合必须按消息归属标记，不能只在媒体表修正而让总览、当前状态和主题继续写错。

只在确定是 AI 回答中的 favicon、引用站点标识或无文字装饰图时跳过分析；AI 生成的架构图、结果图等有意义图片仍要保留。

### 8.2 资源放在输出旁边

GUI 输出统一采用：

```text
课程总结.md
课程总结_images/
课程总结_files/
```

Markdown 使用 URL 安全的相对路径。移动或分享时必须把 Markdown 与两个资源目录一起移动。曾经把图片固定下载到项目根目录 `images/`，导致桌面 Markdown 全部 `Load image failed`。没有使用 Base64 内嵌，因为体积大、编辑体验差且阅读器兼容性不稳定。

命令行历史路径仍有特殊规则：项目根目录 `AI_memory_export.md` 用 `./images/`，移入 `results/export` 或 `results/export_right` 后才改为 `../../images/`。目录层级变化必须同时验证真实链接，不要只改字符串。

### 8.3 文档必须先分层摘要

文本附件先安全提取并生成“附件背景摘要”，再与对话一起综合。不要把整份附件原文直接塞进最终综合，也不要在详细版重复输出原文；曾有详细总结从约 7 千字膨胀到 4 万字，就是重复展示附件全文。

当前原则：

- `.md/.txt/.json/.html/.csv/.docx` 可做安全文本提取；PDF 走既有文档处理。
- 不执行宏、不加载外部引用。
- 文档原文不写入公开总结、日志或完成缓存。
- 只有文件名或权限失效时，保留“原文档不可访问”，不根据历史 AI 回答伪造正文。
- 文件内旧对话、代码、章节和任务只是附件内容，除非当前用户明确讨论它们，否则不能升为当前主题。

## 9. 总结链路的语义约束

### 9.1 Schema 8 的核心观念

模型负责提出候选语义，程序负责最终一致性。每条重要记忆需要保留：

- `topic`；
- `source`；
- `status`；
- `message_ids`；
- 程序确定性生成的 `message_range`。

全部用户原始查询索引、最近 20 条消息（最多 10 轮）由程序确定性保存，不能依赖模型是否觉得重要。`1`、`继续`、`这个怎么改` 等短消息要保留原文并绑定上下文；指代不清时标 `uncertain`。

### 9.2 角色和状态最容易写反

- 用户提出问题 ≠ 用户确认答案。
- AI 已给出事实回答：`answered`。
- AI 已给出代码、文稿或方案但用户未确认采用：`delivered`/建议状态。
- 用户报告运行报错：最多证明 `attempted_by_user`，不能反推所有修改已采用或最终成功。
- AI 解释过知识 ≠ 用户已经掌握。
- AI 结尾“如果你愿意我可以继续”默认不是待办。
- “等待用户提出下一个新问题”不是项目断点，应删除。

编程记录要分开 `assistant_proposed_changes`、`implemented_changes` 和 `implementation_status`。计算记录要分开用户条件与 AI 假设；新条件必须绑定紧随其后的新结果，不能把新条件拼到旧数值上。

### 9.3 分块以完整问答轮次为最小单位

普通轮次不得在用户/AI 边界中间切开，否则新条件可能与上一轮旧回答落入同一块。只有单个轮次本身超过上限时才退到消息或段落级切分。

多分块综合后要检查 `memory_ids` 覆盖，防止只保留最后一块。超长语言学习对话不能把行政区划、中文写作、附件、媒体、计算和编程吞进“英语学习”；语言识别必须有“英语/英文/词汇/语法/翻译请求”等正向证据，并让代码和附件语境优先排除。

### 9.4 三种展示不是三次生成

- 普通版和详细版必须复用同 schema、同原文指纹的结构化 JSON；详细版只增加细节展示。
- 极简版复用普通版 JSON，只输出一个中文“总览”段落，不重新建立语义主链。
- JSON 始终保留完整结构化数据；用户的主题/板块选择只影响 Markdown 展示。
- 普通版与详细版的所有分主题摘要始终完整；重点选择只展开额外详情。
- 媒体开发检查与详细版细节记忆不参与隐藏。

### 9.5 模型弱不等于应该扩大通用规则

Gemini Flash Lite 曾把同一宿舍用电过程拆成两个主题，也生成过残句和过度推断。若原消息、记忆和分块都完整，问题可能主要来自弱模型。不要为了迁就一个兜底模型扩大通用合并规则，除非能证明不会误合并真正独立主题。模型、额度和免费策略都会变；运行时探测和真实质量回归比历史推荐表更可靠。

## 10. API、密钥和数据外发

- GUI 密钥只保存在当前 Windows 用户的 Credential Manager，服务名为 `AI Memory Summary`；供应商顺序也保存在同一凭据存储中。
- GUI 使用用户拖动后的顺序，未配置供应商自动跳过；每个供应商内部仍保留自己的模型回退链。
- 用户在任务运行中修改设置，只对下一次任务生效；当前任务使用启动时冻结的快照。
- GUI 不借用开发环境变量中的密钥；命令行才读取 `GEMINI_API_KEY`、`Silicon_API_KEY`/`SILICONFLOW_API_KEY`、`DEEPSEEK_API_KEY`。
- 自己的 API KEY 绝不能打进 EXE。第一版采用 BYOK 是正确方案；若未来需要免配置体验，应使用受控云端后端，而不是把密钥混淆后塞进桌面客户端。
- HTTPS 可防普通网络窃听，但同一 Windows 用户下的恶意软件、管理员或进程注入仍可能读取运行时密钥；桌面程序无法承诺绝对保密。
- “只抓取”不调用总结 API。普通/详细/极简总结会把对话与可用附件发送给用户选择的模型服务；批量处理私人测试数据前必须获得明确授权。
- 日志、异常、请求参数必须同时脱敏三类密钥，不记录完整分享链接或带签名下载地址。
- Git 远端凭据应交给 Git Credential Manager；不要把 Token 写入 `.git/config` 的 URL，也不要让 `git remote -v` 把含 Token 的 URL 打印进任务日志。

## 11. 缓存、日志和性能

### 11.1 真正的耗时在哪里

本地 Markdown 解析、分块和渲染通常只有毫秒级；主要耗时来自：

- 浏览器加载和滚动等待；
- 图片/附件网络下载；
- 媒体分析；
- 每个文本分块的模型请求；
- 最终全局综合；
- 用户登录和主题选择等待。

历史上 497 秒任务中约 359 秒是人工选择等待；另一次 589 秒中约 280 秒是人工等待。界面和日志应分开“程序处理”和“人工等待”，不能只给一个总时间。

### 11.2 已验证有效的无损优化

- 图片下载有限并发、URL 去重；已有图片目录也保持并发。
- 完成缓存严格绑定消息、模型配置、媒体内容和总结代码；任一变化都应失效。
- 普通版/详细版共享结构化结果。
- 模型/供应商回退复用已经完成的媒体分析和分块，只重试未完成阶段；不要每切一次模型就重跑全部工作。
- 每个阶段记录耗时、缓存命中和错误类型。

曾有 27 个图片引用，其中 favicon 重复失败并各等 10 秒，图片阶段拖到 238 秒。优化后只处理 4 张真实图片，同一链接图片阶段约 2 秒。性能排查先看结构化日志，不要先改总结质量相关的分块和提示词。

### 11.3 运行数据位置

- 源码模式默认在项目根目录保存运行数据。
- 打包版默认在 `%LOCALAPPDATA%\AI Memory Summary`。
- 用户可在设置中改到其他磁盘；浏览器资料、日志、缓存和调试快照随新目录使用。
- 更换目录不会迁移或删除旧目录，新的浏览器资料可能要求重新登录。
- `.browser_user_data` 含 Cookie/会话，属于敏感数据；不要提交、复制到他人机器或随便清空。

## 12. 测试和验收基线

### 12.1 离线测试

本次交接时：

```text
Ran 214 tests in 11.673s
OK
```

离线测试使用模拟网关，不应读取真实 API KEY，也不调用外部模型。新增非平凡分支、循环、解析或安全逻辑时，至少留下一个最小回归测试，再跑全量。

### 12.2 真实网页回归

`tests/tests.txt` 覆盖分享页和账号内页面，包括图片、文档、超长对话、公式与补充样例。真实测试要注意：

- `tests.run_tests` 会联网抓网页，但不调用总结 API；
- 批量总结会向外部模型发送测试对话和媒体，需明确授权；
- 分享链接和平台 DOM 会失效，测试失败不一定是代码回归；
- 真实抓取必须同时核对内容，不只看进程退出码。

### 12.3 黄金基线

`results/export_right/baseline_manifest.json` 当前包含 7 份人工确认基线：

- ChatGPT：含图片、含文档、超长文档；
- DeepSeek：含图片、超长对话；
- 豆包：含图片、含文档。

DeepSeek 超长基线允许 1 个已知失效图片占位；ChatGPT 数学公式被排除，因为当前抓取是验证页。对比顺序：先哈希；不一致时再比较消息数量、角色、首尾、多处中段关键字、资源引用与正文规范化。动态图片文件名变化不等于内容回归，应比较实际字节或归一化引用。

注意：整个 `results/` 被 Git 忽略，黄金基线只存在本机。新队友若需要真实回归，必须从负责人处获得该目录的可信副本，不能以空目录或新抓取结果自封为“正确答案”。

## 13. 已知外部限制与正确退让

### 13.1 分享页资源已经失效

ChatGPT/DeepSeek 可能仍显示文件名、file ID 或签名路径，但官方端点稳定返回 401/403/404。浏览器偶尔能显示也可能只是 SPA 内存、Service Worker 或旧缓存。只允许一次受控站内重挂载与官方端点验证；仍失败就：

- 保留文件名和失败原因；
- 标记不可重新验证；
- 保留对话文字和历史 AI 判断，但明确它不是当前重新识别结果；
- 停止重试，不绕过鉴权，不根据回答伪造附件正文。

### 13.2 模型结果具有随机性

相同原文重跑可能出现：主题拆分不同、残句、英文输出、夸大数量、把建议写成事实、把 AI 回答写成用户决定。程序已有大量确定性兜底，但“测试通过”不代表语义绝对正确。面向发布的样例仍需人工与 export 对照。

### 13.3 轻量版依赖真实机器环境

Edge 和 Chrome 曾完成真实兼容测试，但最新代码的轻量版尚待本轮人工验收。离线“选择顺序测试通过”不能替代解压后双击 EXE、真实登录、抓取、附件和总结全链路测试。

## 14. 常见故障速查

| 现象                   | 优先怀疑                 | 先检查什么                               |
| -------------------- | -------------------- | ----------------------------------- |
| `run_tests` 卡住不动     | 页面超时后旧进程仍在等导出文件      | 进程是否加载旧代码、是否有非零退出、日志最后阶段            |
| 长对话开头/中间缺消息          | 虚拟列表未完整采集            | 虚拟键/消息 ID 是否连续，首尾是否复采               |
| 附件刷新后消息变少            | 新快照覆盖了完整旧快照          | 是否先冻结消息，只补资源不删正文                    |
| 图片已下载但 Markdown 加载失败 | 相对路径或资源目录层级错误        | `.md` 与 `_images` 是否在一起，URL 编码是否正确  |
| 图片存在却写“不可访问”         | 把 API 分析失败混成文件缺失     | 本地文件状态、媒体状态、ConnectError/503 日志     |
| 两张图变四张/十张            | SVG 懒加载占位或重复界面图标     | 豆包 HTML 中空 SVG、`img-z0eKj1`、同消息重复引用 |
| ChatGPT 两张图互换        | 全局资源顺序绑定消息           | 是否按线性会话数据和具体消息绑定                    |
| PNG 只有约 600 字节       | 保存了签名元数据 JSON        | 校验文件头，并继续下载 JSON 中真实 URL            |
| 已登录却反复要求登录           | 无头 ChatGPT 私有页返回空白   | 改用最小化有界面模式，不要先判登录失效                 |
| 每下载一个文档就弹窗           | 导航后没有重新最小化           | 每次点击/返回后调用窗口最小化                     |
| DeepSeek 只总结后半段      | 网页引用误报文档或记忆覆盖缺失      | 原消息数、附件数、分块、`memory_items` 覆盖       |
| 文档内容变成独立英语主题         | 附件边界丢失               | 最终模型是否只看到附件摘要，词汇规则是否先排除附件           |
| 总结极慢                 | 重复资源、API 超时、回退重跑全部阶段 | JSONL 阶段耗时、图片去重、缓存命中、模型/供应商切换       |
| 测试缺 `markdownify`    | 用了系统 Python          | 改用 `.venv\Scripts\python.exe`       |
| 改完结果没变化              | GUI 未重启或旧产物未重跑       | 关闭 GUI，删除/避开旧缓存，重新生成                |
| Summary 显示完整但语义怪     | 模型弱或状态兜底不足           | 与 export 对照角色、数字、条件和消息来源            |

## 15. 安全的修改流程

建议每项任务都按下面做：

1. 读 `agents.md`、本交接、相关代码和已有测试。
2. `git status --short --branch`，确认当前分支和用户已有改动；不要覆盖他人工作。
3. 用现有失败产物或 `tests/tests.txt` 的具体样例复现。
4. 明确问题层：页面采集、平台解析、资源下载、统一消息、总结、渲染、缓存、GUI 或打包。
5. `rg` 搜索目标函数所有调用方和相邻平台实现。
6. 只改根因所需的最少文件；平台问题优先平台限定。
7. 加一个能失败的最小测试，再跑 `python -m unittest discover -v`。
8. 只有离线测试无法证明时才做真实网页/GUI/API 回归；涉及私人数据外发先取得授权。
9. 核对 `git diff --check`、`git diff` 和 `git status`，确认没有密钥、日志、浏览器资料、结果目录和构建目录。
10. 报告已验证内容、没验证的边界和已知外部限制。除非负责人明确要求，不 commit、不建分支。

回滚也要谨慎。曾有用户明确要求“不用 Git 恢复”，因此不要默认用 `git checkout`、`reset` 或 `clean`。若确需删除或恢复，先确认精确目标与可恢复性。

## 16. 打包与交付

全量版采用 PyInstaller `onedir`，内置 Playwright Chromium。构建命令见 `README.md` 和 `AI_Memory_Summary.spec`。交付时：

1. 发送完整 ZIP 和 SHA-256 文件。
2. 用户完整解压，不能在压缩软件里直接运行。
3. 不能只发送 EXE；`_internal` 中有 Python、Chromium 和依赖。
4. 未购买商业代码签名证书，SmartScreen 可能提示“未知发布者”；应核对哈希，不要要求用户关闭杀毒软件。
5. 解压后执行冻结环境冒烟，再做至少一条真实抓取和一条总结。

轻量版不内置 Chromium，优先 Edge、后备 Chrome。其体积小，但更依赖用户机器的浏览器版本和策略；必须分别验证 Edge、Chrome、登录资料隔离、私有 ChatGPT 最小化流程和“无浏览器时提示下载全量版”。

构建目录、解压副本、`__pycache__` 和一次性冒烟 JSON 通常可重建，但不应擅自删除。历史清理曾一次释放数 GiB，也曾因永久删除导致只有受 Git 跟踪的少量文件可恢复；删除前必须列清目标、大小和恢复方式。
