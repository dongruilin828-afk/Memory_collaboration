# 同批截断反馈预拆分实施计划

**Goal:** 用户已授权实施上一轮建议：自动模式将已确认截断反馈用于后续相似分块，减少先截断再拆分的请求。

**Spec:** 本会话已确认的优化建议及用户“进行优化”；沿用局部分块修复和分支进度，不更改并发10上限、不提交或创建分支。

**Architecture:** 批次调度器仅在内存中保存截断样本。按接口凭据池、模型/协议、思考及reasoning设置、输出预算、JSON模式、来源平台、消息平均长度的log2档位隔离。样本保存失败字符数与原局部修复的目标字符数；后续未完成分块达到同档失败长度的80%时使用该目标，至少1000字符。若同档再次截断，才继续收紧；本批结束后清空，避免跨批误用。

**Tech Stack:** Python标准库、现有AdaptiveSummaryScheduler、ConversationChunk与进度拆分树、unittest及本地HTTP/Chromium。

## 实施与验证

- [x] `scripts/adaptive_concurrency.py`：增加批内截断样本及`chunk_target`/`record_chunk_split`，加条件锁，轨迹仅保存受控模型、字符数、密度档位和目标；超时/JSON错误/媒体和综合阶段不参与学习。
- [x] `scripts/gemini_summarizer.py`：成功缓存及已保存拆分优先；发起新分块提取前读取建议，复用原分块器、稳定子块编号和进度树。预测拆分与失败修复共用每条路径最多3层的限制，取消后沿保存计划续跑；恢复已成功块不因后来的学习而重新编号或拆分。
- [x] `tests/test_predictive_chunk_sizing.py`：核对同文件后续块、跨文件学习、接口/模型/思考/输出/平台/密度隔离、较小块不误拆、并发反馈、取消恢复、上限、默认模式隔离及轨迹脱敏。保留旧局部修复测试和GUI调用回归。
- [x] 最终在`tests/test_results/05_截断反馈预拆分最终验证_20261031`保存本轮新抓取、三种总结、专项证据及一次最终测试；本地故障响应验证，无收费模型调用或桌面写入。

最终验证461项通过（40界面、421后端），0失败/错误/跳过。11项新增专项含真实HTTP截断学习和跨文件预拆分。4份新Chromium本地网页抓取、5项文件任务、15份三种总结与HTTP轨迹均在本轮05目录。并发上限及默认/手动入口保持原规则，未创建分支或提交推送。

## 复核重点

- 更早已成功的块和缓存先复用，不因新策略失效。
- 相似度是有界启发式，不能保证零截断；无证据的模型、配置和密度档位沿原策略。
- 进度树含预测拆分原因，重排仍保留原消息角色/编号及已有记忆ID。
- 不按一次超时降低所有模型分块，不增加主动测速请求。
- 后续请求仍逐次领取许可并使用原失败预算、取消与回退机制。
