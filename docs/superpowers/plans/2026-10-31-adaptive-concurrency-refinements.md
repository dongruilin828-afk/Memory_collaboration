# 文件自动并发优化实施计划

**Goal:** 实现已获用户确认的请求轨迹、回退负载迁移、冷启动探索和故障恢复四项优化。

**Architecture:** 继续使用批次内调度器和标准库；文件上下文绑定真实请求及可变预留，生产批次目录保存 JSONL 事件。每次传输仍领取许可，全局真实请求上限 10。

**Tech Stack:** Python、threading.Condition、threading.local、JSONL、现有 unittest 和本地 HTTP/Chromium 验证。

**Spec:** 本轮用户“按你的建议开始优化”，承接前一轮四项优先建议；直接在现有分支实现，不提交或推送。

## 约束与选择

- 仅作用于已有文件自动模式；不改抓取、平台语义、手动并发及 API 选择范围，不发送测速请求。
- 轨迹保留文件编号、请求编号、接口匿名池编号、配置标识、模型、阶段、起止时间、等待/耗时、容量、错误类别与回退关系；不写正文、原路径、地址、Key 或 Key 指纹。
- 首次连续两次成功、运行至少 2 秒且仍有排队文件时可从 1 增至 2；后续继续按四次稳定成功扩容。发生错误即退出首次探索。
- 连续两次传输故障开始冷却，后续冷却 2/4/8…最多 60 秒；恢复阶段仅放行一个真实请求。旧的在途成功不得撤销较新的故障降速。
- 仅自动模式限制重复失败的重试：进入恢复阶段或累计失败调用耗时达到一次请求超时预算时，不继续当前逻辑请求的重试，交给已有回退处理。许可等待最多 60 秒且可取消，不能提前突破 Retry-After。
- 暂不实现吞吐窗口优化、复杂任务估算或跨批次历史，先积累轨迹验证。

## 实施与核对

- [x] 调度器：新增文件上下文、脱敏 JSONL、峰值及当前/上次调整状态；测试日志不含凭据、取消释放、同池共用及磁盘写入失败。
- [x] 回退：service 在主 API 尝试前迁移文件预留；媒体 API 请求只记真实使用，不迁移主文件预留；核对结束后负载归零。
- [x] 冷启动及恢复：确定性时钟验证两次成功探索、错误后退出、逐步冷却、单请求恢复、旧成功竞争和重试停止。
- [x] 队列：文件结束释放预留后再保存最终状态；专项核对最终处理中/活动请求为零；最终 HTTP 轨迹核对列入下一项。
- [x] 最终定版后一次保存相关回归、新抓取与三种总结到 `tests/test_results/10_自动并发优化最终验证_20261031`；438 项回归通过，4 文件生成 12 份总结 Markdown，13 次真实本地 HTTP 尝试及一次回退全部配对，峰值 2 与服务端一致，结束后活动请求、任务与负载归零。

最终验证的 HTTP 阶段曾因脚本配置 ID 不符合 `custom_[0-9a-f]{32}` 被入口拒绝；仅修正验证脚本并重跑 HTTP 阶段，保留同一目录内本次新抓取输入和已完成回归记录。产品实现未变，没有重复计算通过数。未调用真实账号或付费模型，未提交或推送。
