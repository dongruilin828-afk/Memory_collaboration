# 失败分块局部修复与分支进度实施计划

**Goal:** 已获用户授权：截断仅拆失败分块，保留成功分块；模型回退后恢复相应分支，保持并发上限和现有自动恢复策略。

**Architecture:** 仅自动文件总结显式启用。复用完整输入/模型/媒体配置指纹，为每个分支建立独立进度文件；缓存媒体说明、成功叶块与拆分决策。通过现有分块器按真实消息映射拆分失败块，不猜消息编号；分块ID独立分配并持久化，保持记忆引用稳定。

**Tech Stack:** Python标准库、现有ConversationChunk/规范化与调度器、unittest及本地HTTP/Chromium。

## 约束与执行

- [x] 自动模式进度路径以完整指纹隔离，绑定配置/实现、原文、模型、思考设置、平台及原媒体；实际媒体说明变化后失效依赖块及拆分决策。旧无绑定进度不猜测迁入，默认/手动入口仍用原有规则。
- [x] 只对明确SummaryOutputTruncatedError局部拆分；保留完整问答轮次，必要时拆长消息，保留真实原始消息ID和角色。单条路径最多3层、目标至少1000字符，不能缩小时按原回退；既有失败预算/取消/恢复仍生效。
- [x] 成功叶块独立保存，拆分决策在发送子块前落盘；取消、子块失败、换API和恢复不得覆盖其他分支。子块使用独立稳定chunk_index，完成后按原顺序综合，不重编号已成功记忆。
- [x] service透传新行为，并阻止已局部尝试过的截断再触发整文件缩块；无关平台和默认入口不扩大改动范围。
- [x] 核对局部修复、原块/子块续用、跨API回返、不同媒体/思考/模型隔离、消息归属、记忆ID唯一、取消与修复上限；最终新抓取/三种总结与必要证据统一保存到tests/test_results新的编号中文目录，不调用收费模型，不创建分支或提交推送。

最终验证：450项通过，0失败/错误/跳过；本轮4份真实Chromium本地网页抓取、5项文件任务（含重复输入）、15份三种总结及完整HTTP请求轨迹保存在 `tests/test_results/04_局部分块修复与分支进度最终验证_20261031`。局部截断和缓存分支使用9项生产编排专项用例验证，未调用收费模型。
