# 分块成功反馈放宽目标实施计划

**Goal:** 用户已授权：在批内截断预拆分上加入连续成功与输出余量反馈，减少过碎分块，保留成功块和原有恢复规则。

**Spec:** 本会话已确认的必要优化及用户“进行优化”。采用本会话原生执行，不创建分支、提交或推送；并发上限保持10。

**Architecture:** 复用同接口凭据池/模型/思考/输出/平台/消息密度的批内记录。已有截断样本才允许回升，连续3个新生成且校验成功的同类块、块长至少当前目标50%、实际输出用量不超过配置预算60%，且按候选块长线性估计的输出不超过预算75%时，目标增加25%；最大为已截断规模80%及配置分块上限中的较小者。成功反馈只影响后续未保存拆分的块；不改现有拆分树或缓存。每次截断与放宽均推进反馈轮次，旧在途成功不得覆盖新轮次。边界测试将覆盖下限从60%调整到50%，避免第一次放宽后既有拆分树的成功块立即被当作小尾块；预计输出的额外25%余量约束同步加入。

**Tech Stack:** Python标准库、现有网关受控usage元数据、AdaptiveSummaryScheduler与进度树、unittest/本地HTTP/Chromium。

## 实施

- [x] `scripts/adaptive_concurrency.py`：将截断记录扩展为目标/失败规模/连续成功/轮次。增加成功反馈方法；缺失/非法用量、预算不一致、输出接近上限、块太小时不扩张。旧轮次忽略；再次截断立即收紧和清零。
- [x] `scripts/gemini_summarizer.py`：实际JSON分块响应使用线程局部受控元数据，并绑定本次实际输出上限；分块规范化、专项核对及进度落盘成功后才提交成功反馈。缓存、媒体和综合不计入。Gemini计入独立思考用量，缺失该信息则不放宽。
- [x] `tests/test_chunk_success_feedback.py`：14项专项核对阈值、限幅、无样本/无usage/高用量/小块/变更预算保护、配置隔离、连续与并发轮次、再次截断、默认入口与缓存不计入，以及真实HTTP贯穿网关和总结编排；请求及专项核对阶段的本地排队/预算暂停均不清除已有成功反馈。
- [x] 最终回归与本轮新抓取、三种总结及必要证据统一保存到`tests/test_results/06_成功反馈分块回升最终验证_20261031`。不调用收费模型，不写桌面，保留全部旧结果。

最终实现统一回归475项通过（40界面、435后端），0失败/错误/跳过，测试期间核对实现SHA未变化。真实HTTP两文件对照从20次请求降为16次，第一文件的原拆分保持不变；新抓取4份本地网页会话，5项文件任务（含重复输入）输出15份三种总结及必要JSON/轨迹。全部最终产物集中在06目录。

## 复核重点

JSON解析成功不代表专项核对通过；实际请求预算不一定等于配置预算；思考与正文可能分别计量；旧在途反馈不能抵消新截断；完成缓存不得重复累计成功样本。
