# 自动批次排队、回退与复用实施计划

**Goal:** 根据36文件真实批次暴露的问题，落实已授权的五项优化，保持全局真实请求上限10。

**Architecture:** 复用现有调度器、完成缓存指纹与service回退链。只在文件自动模式注入新行为；使用标准库条件锁维护短暂挂起、批次内重复任务及请求预算，保留逐项输出与主题选择。

**Tech Stack:** Python标准库、现有GUI队列、unittest、本地HTTP及Chromium。

**Spec:** 用户本轮“进行改动”，承接上一轮五项优化建议；不创建分支，不提交或推送。

## 行为与边界

- 本地许可等待3秒后返回独立的延后信号，任务短暂回队列，不算API失败；同一文件累计许可等待最多900秒、实际网络请求预算为两倍配置单次超时，主题选择不计入预算。保留进度并可取消。剩余网络预算也约束当前真实传输。
- 首次分配及后续回退参考有效容量、在途负载、冷却、恢复及近期传输故障；仍限定所选API，候选实际失败后不无限循环。
- 在主API调用前检查所有允许候选的精确完成缓存；正文、附件、平台、模型、思考设置、实现等沿用已有完整指纹。相同候选指纹集合的在途任务只执行一次结构化生成，其他任务延后并复用完成缓存；失败、unclear或不可缓存结果不共享为成功。
- 容量使用最近12次、最多180秒的传输反馈，间歇超时不会被一次成功全部抹掉；保留旧请求故障轮次保护、单请求恢复及稳定扩容。
- 轨迹只补记受控finish_reason、数值token用量和错误类型；不存正文、端点或凭据。自动模式明确识别length，较长输入在同一API最多缩小分块修复一次，保留有效媒体与总体预算；默认入口不变。

## 实施与验证

- [x] 调度器和队列：可恢复延后、负载释放、取消、累计预算、间歇故障窗口与动态回退评分。按同类请求最近四次完成吞吐判断是否暂缓扩容。
- [x] 总结入口：精确缓存预检、批次内重复执行抑制、受控响应元数据及一次分块修复。预检在同一输入内复用本地媒体读取与哈希，避免每个候选重复解析附件。
- [x] 专项：本地排队不导致文件失败、繁忙API跳过、失败重试有界、重复输入/不同附件及配置不串用、输出和主题选择独立、默认模式隔离。新增15个场景，默认入口隔离问题在扩展回归中发现并修复。
- [x] 最终一次回归及新抓取/三种总结保存在 `tests/test_results/02_自动排队回退与缓存最终验证_20261031`；433项通过，4份新抓取输入、5个任务、15份总结Markdown及10份JSON。真实本地HTTP共14次，其中13次成功与一次401回退；重复任务复用结构化结果，终态活动请求和负载归零。未使用真实账号或付费模型，未提交或推送。
