1. LongMemEval——强烈建议加入

Wu, D., Wang, H., Yu, W., Zhang, Y., Chang, K. W., & Yu, D. (2025). LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory. ICLR 2025.

这篇论文与你们项目的关系非常直接。

它专门研究聊天助手的长期记忆能力，设计了 500 个问题，并从五个方面评估长期记忆：

  • 信息提取
  • 多会话推理
  • 时间推理
  • 知识更新
  • 拒答/不确定性处理

研究还把记忆系统拆分成 indexing—retrieval—reading 三个阶段。加州大学洛杉矶分校计算机科学系

尤其值得你们引用的是，它发现即使是商业聊天助手和长上下文模型，在持续交互中的记忆能力仍然存在明显下降。加州大学洛杉矶分校计算机科学系

对应你们申请书：

你们目前已经提出：

“通过问答、测试任务续接状况验证其能否正确恢复已有背景、状态。”

因此可以直接把 LongMemEval 引入你们的评测设计。

2. MemBench——补强“评测基准”方向

Tan, H., Zhang, Z., Ma, C., Chen, X., Dai, Q., & Dong, Z. (2025). MemBench: Towards More Comprehensive Evaluation on the Memory of LLM-based Agents. Findings of ACL 2025, 19336–19352. DOI: 10.18653/v1/2025.findings-acl.989.

这是我认为你们最值得补进“研究现状”中的第二篇。

它指出现有记忆评测存在两个问题：

  1. 记忆层次覆盖不够丰富；
  2. 交互场景不够多样。

因此 MemBench 同时考虑：

  • factual memory（事实记忆）
  • reflective memory（反思性记忆）
  • participation（参与式交互）
  • observation（观察式交互）

并从effectiveness、efficiency、capacity多个方面评价 Agent 的记忆能力。ACL Anthology

这和你们申请书中的：

“抓取完整性、总结事实一致性、关键内容覆盖全面性、跨模型迁移有效性”

非常容易形成对应关系。

3. MemoryBench——特别适合“用户侧记忆 + 用户反馈”

Ai, Q., Tang, Y., Wang, C., Long, J., Su, W., & Liu, Y. (2025/2026). MemoryBench: Benchmarking Memory and Continual Learning in Large Language Model Systems.

这篇尤其值得关注，因为它不只是问：

“模型能不能记住？”

而是进一步研究：

模型能不能在长期服务过程中，根据不断累积的用户反馈持续学习？

MemoryBench 构建了一个用户反馈模拟框架，并覆盖多个领域、语言和任务类型，用于评价 LLM 系统的持续学习能力。该项目 2025 年首次提交，2026 年仍在持续更新。alphaXiv+1

这与你们“用户选择什么值得长期记住”的设计非常契合。

你们目前已经提出：

“先由系统识别一个会话中的不同话题，再由用户选择哪些话题重要。”

因此可以把 MemoryBench 引入后，把你们的研究问题进一步表述为：

“AI 自动记忆” → “用户参与的可控记忆” → “长期持续交互中的记忆更新与维护”。

这个变化会让你们的研究现状明显更贴近 2025–2026 年的研究趋势。

4. Portable Agent Memory——最直接对应“跨平台 + 可导出”

Ravindran, S. K. (2026). Portable Agent Memory: A Protocol for Cryptographically-Verified Memory Transfer Across Heterogeneous AI Agents. arXiv:2605.11032.

这一篇和你们的项目定位几乎是直接对应关系。

论文明确提出：

不同 AI Agent 的长期记忆目前往往锁定在各自的厂商运行环境中。

因此提出一个用于异构 AI Agent 之间传输持久化记忆的开放协议。其设计包括：

  • 结构化记忆模型
  • 可验证的记忆来源
  • 权限控制
  • 跨模型记忆迁移
  • JSON-first 序列化
  • GPT、Claude、Gemini、Llama 等不同模型之间的记忆迁移 arXiv+1

这个方向与你们申请书中的核心创新点：

“构建‘用户侧可移植记忆层’”

以及：

“以开放文档形式作为跨平台的中间载体”

高度一致。

这一篇我建议一定加入。

甚至可以利用它来重新强调你们项目的创新空间：

现有研究开始探索 Agent 之间的记忆协议，但针对普通用户已有聊天记录的用户侧提取—开放格式导出—人工编辑—跨平台迁移仍有进一步研究空间。

这比单纯说“现有平台之间不能互通”要严谨得多。

我建议你们把原来的“研究现状”改成这个结构

你们现在的 2.1–2.4 结构其实已经不错，但如果要体现 2025、2026 最新进展，我建议增加一个新的小节：

2.5 用户侧记忆、跨平台迁移与记忆评测成为新的研究方向

可以直接写成下面这种风格：

近年来，大语言模型记忆研究开始由模型内部的长期记忆机制逐渐拓展至用户侧记忆管理、跨系统迁移以及标准化评测。 LongMemEval 针对长期交互式聊天助手提出系统性的记忆评测框架，从信息提取、多会话推理、时间推理、知识更新和拒答等维度评价模型的长期记忆能力，说明仅依靠扩大上下文窗口并不能充分解决长期交互中的记忆问题[10]。MemBench 进一步从事实记忆、反思性记忆以及不同交互场景出发，对 LLM Agent 的记忆能力进行综合评价，推动记忆研究由单一的“能否记住”向有效性、效率和容量等多维评价发展[11]。MemoryBench 则将用户反馈引入持续学习过程，通过模拟长期服务中的用户反馈，评价大语言模型系统能否在持续交互中积累和利用经验[12]。

与此同时，记忆的所有权和跨平台可迁移性开始成为新的研究问题。 Portable Agent Memory 提出了面向异构 AI Agent 的持久记忆迁移协议，通过结构化记忆表示、访问控制和序列化机制实现不同 Agent 之间的记忆传输[13]。这一方向表明，AI 记忆正在从封闭于单一模型或平台内部的状态，逐渐向具有开放表示和跨系统互操作能力的用户侧记忆发展。对于普通用户而言，如果能够进一步将已有对话转换为结构化、可编辑、可导出的记忆文件，则可以降低不同 AI 平台之间的上下文迁移成本。

国内相关研究也开始将记忆作为智能体体系的重要组成部分。 李航从 AI Agent 的总体架构出发，将记忆模块与大语言模型、工具模块等共同纳入智能体系统，为国内智能体记忆研究提供了体系化视角[14]。总体来看，当前研究已经在长期记忆机制、记忆评测和 Agent 内部记忆方面形成较丰富成果，但面向普通用户的“会话获取—记忆整理—用户选择—开放格式导出—跨模型迁移”完整链路仍相对缺乏。因此，本课题从用户侧出发构建可移植记忆层，具有一定的研究和应用价值。

这个版本会比你现在的 2.4 更能体现 2025–2026 年的研究进展。
