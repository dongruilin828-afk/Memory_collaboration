# 数据结构作业：PJ1

## 概述

在本项目中，你需要实现一个 **AVL 树** 和一个 **红黑树**，比较它们的实证性能，利用理论性质解释其差异，并针对红黑树提出一种可能的改进方案。这两种树必须对外暴露相同的有序集合（ordered-set）接口，以便实验比较的是数据结构本身而非无关的代码程序。你可以使用课程批准的任意编程语言。除非任务中另有明确说明，否则实现代码、正确性证明和性能分析必须由你独立完成。

每个节点存储一个可比较的值（例如 64 位有符号整数），值本身决定了大小顺序。节点值是唯一的：插入已存在的值不会创建第二个节点。除非另有说明，查找或删除失败属于正常操作，不得导致程序崩溃。

## 1. 通用接口与规范

为每种树结构提供以下逻辑操作的实现。方法名称可根据编程语言习惯有所不同，但含义和返回值必须在 `README` 中说明。

| 操作 | 必须实现的行为 |
| --- | --- |
| `insert(value)` | 插入指定值；返回是否插入了新值。 |
| `find(value)` | 返回该值是否存在。 |
| `erase(value)` | 如果存在则移除该值；返回是否发生了移除。 |
| `size()` | 返回当前存储的值的个数。 |
| `empty()` | 返回树是否为空。 |
| `clear()` | 移除所有值并释放所占用的内存。 |
| `inorder()` | 按严格递增顺序返回或遍历所有值。 |
| `height()` | 使用某种明确声明的规范返回树的高度（必须说明空树的高度定义）。 |
| `validate()` | 检查元素顺序以及所有的平衡/颜色不变量（用于测试）。 |
| `print_standard()` | 打印第 4 节中要求的标准层序/递归表示形式。 |

公共接口**不得**泄露特定实现的平衡调整步骤。树拥有其节点的所有权，不得发生内存泄漏。如果红黑树使用了哨兵节点（`NIL`），需说明其是否计入树的高度的计算或输出中（**绝对不能**将其作为数据节点打印出来）。

> **AI 使用规定：** **禁止使用**。AI 仅可用于澄清语言语法或工具链的使用，不得用于设计、实现或解释这些接口。

## 2. AVL 树

实现一个支持第 1 节中所有操作的 AVL 树，包括插入和删除时的重新平衡（Rebalancing）。每个真实节点必须维护足够的元数据以高效计算平衡因子（通常是高度或平衡状态字段）。在每次成功更新后，所有节点必须满足 AVL 不变量：



$$
\vert{}h(\text{left}) - h(\text{right})\vert{} \le 1
$$



实现并使用四种旋转情况（LL、RR、LR、RL），或等价拆分为单次旋转的操作。

你的报告必须包含更新重平衡的伪代码或简要解释、不变量的证明概要，以及查找、插入、删除和额外空间复杂度的最坏情况渐进界限。同时需注明代码中使用的高度规范。

> **AI 使用规定：** **禁止使用**。AI 不得编写或重写 AVL 的实现代码、平衡逻辑、伪代码、证明或复杂度分析。

## 3. 红黑树

实现一个支持相同接口的红黑树。可以使用共享的 `NIL` 哨兵节点或 `null` 子节点，但必须明确说明说明你的选择。每个真实节点必须包含颜色属性，实现代码必须维护以下不变量：

1. 每个节点要么是红色，要么是黑色；根节点是黑色。
2. 所有 $NIL/null$ 叶子节点都被视为黑色。
3. 红色节点的子节点必须都是黑色。
4. 从任意节点到其后代 $NIL$ 叶子节点的所有路径上，包含相同数量的黑色节点。

必须实现插入修复（Insertion fix-up）和删除修复（Deletion fix-up）；不得使用标准库的有序集合或树函数替代你自己的实现。报告中必须解释每种修复步骤处理的情况，给出不变量维持的证明概要，并给出所有必需操作的最坏情况界限。

> **AI 使用规定：** **禁止使用**。AI 不得编写或重写红黑树实现、修复情况处理、伪代码、证明或复杂度分析。

## 4. 标准树输出与可测试性

两种实现都必须提供 `print_standard()`（或文档中说明的等效函数），输出格式必须是确定性的、可进行逐字节对比的结构。使用括号递归打印树：每个真实节点写为 `(value left right)`，其中 `left` 和 `right` 是其子节点的括号表示形式。缺失的子节点写为 `()`，因此空树表示为 `()`。

* 对于 AVL 树，仅打印节点的值。
* 对于红黑树，打印节点值及其颜色标志 `:R` 或 `:B`；**不要**打印高度元数据。
* 节点内部的标记用单个空格分隔，结尾不要添加多余空格。

例如，一个有效的红黑树输出如下：

```Plaintext
(10:B (5:R () ()) (15:B (7:B () ()) ()))
```

如果你的编程语言无法保持文本字面格式，请提供一个包含完全相同 Token 的确定性文本文件输出，并说明调整方式。测试部分需包含针对空树、重复插入、失败操作、已排序及逆序插入、所有旋转/修复情况的自动测试，以及在随机混合操作后调用 `validate()` 进行的不变量检查。

> **AI 使用规定：** **允许使用**，但仅限于标准输出格式化、测试用例设计和测试代码编写。数据结构的实现代码和不变量检查逻辑必须由你亲自编写。

## 5. 性能实验与理论分析

对两种树使用统一的驱动程序（Driver）和完全相同的操作序列。至少测量跨越一个数量级以上的三个输入规模（例如 $10^3$、$10^4$ 和 $10^5$ 个值，具体可根据实际限制调整）。测试负载必须至少包含以下场景：

1. 随机唯一值插入；
2. 顺序插入（Sorted insertion）；
3. 逆序插入（Reverse-sorted insertion）；
4. 包含成功查找、失败查找、插入和删除的混合负载。

在计时前进行预热（Warm up），计时区域内**排除**输入生成和打印的时间；每个测量重复足够的次数以报告稳定的统计数据，并说明你报告的是均值、中位数还是其他统计量。在每个工作负载结束后验证正确性并调用 `validate()`。报告实际经过的时间（Wall-clock time），如果条件允许，还可记录比较/旋转/重配色计数器。展示表格或图表，并解释性能波动的来源。

将测量结果与理论联系起来：对比 AVL 树的高度界限 $O(\log n)$ 与红黑树的高度界限（最高为 $2 \log_2(n+1)$）；解释为什么 AVL 树可以拥有更短的查找路径，而红黑树的更新操作所需的重平衡可能更少。讨论性能对工作负载的依赖性，而不是简单声称某种数据结构普遍更快。

> **AI 使用规定：** 对于实验设计决策、数据收集、数据解读、理论解释和绘图，**禁止使用 AI**。仅在第 4 节允许的范围内可以使用 AI 生成的绘图/测试样板代码；所有数据必须来自你自己的运行结果。

## 6. 红黑树改进建议

根据你的测量结果以及文献/AI 辅助的研究，探讨改善红黑树或相关平衡二叉搜索树的一个可能方向。以下是几个宽泛的研究方向，你可以选择其中之一或提出其他有据可查的方向：

* 并发与并行处理；
* 感知工作负载（Workload-aware）的结构与操作。

说明核心思想、预期收益以及主要权衡（Trade-off）。明确区分已实现的结果和提议的研究方向，并在适当位置引用相关文献来源。
