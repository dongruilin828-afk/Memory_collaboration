# C 题本地部署约束与三人并行工作表

更新日期：2026-09-10

本文件把 C 题规划转换为团队执行约束。角色名称暂用“队员 A/B/C”，确定姓名后只替换负责人列，不改变任务边界。

## 一、本地部署硬约束

### 1. 统一运行环境

所有成员必须从同一份 `pyproject.toml`、`uv.lock` 和 `.python-version` 建立环境。

| 项目 | 统一值 | 验收命令 |
| --- | --- | --- |
| Python | 3.13.9 | `uv run --locked python --version` |
| uv | 0.12.12 | `uv --version` |
| 依赖安装 | 严格使用锁文件 | `uv sync --locked` |
| 脚本运行 | 由 uv 选择项目环境 | `uv run --locked python scripts/<脚本>.py` |
| 依赖检查 | 不允许冲突 | `uv pip check` |

首次部署：

```powershell
cd <项目根目录>
uv --version
uv sync --locked
uv run --locked python --version
uv pip check
```

若 `uv` 或 Python 版本不一致，先统一工具版本再运行项目。禁止用全局 `pip install` 修补项目依赖，禁止只修改 `pyproject.toml` 而不更新并共享 `uv.lock`。确需增删依赖时，由计算负责人统一修改，其他成员暂停同步环境，待新锁文件复核后再执行 `uv sync --locked`。

### 2. 数据与时间口径

- `data/raw/` 仅保存题目原始附件，禁止覆盖、重命名、手工改值或另存后替换。
- 所有 10 分钟数据使用整数时段 `slot=0..143`；原 Excel 时间仅保留为展示字段。
- 功率统一用 kW，时段能量统一用 kWh，换算固定为 `energy = power / 6`。
- 日期统一使用 `YYYY-MM-DD`；问题 2～4 按日期连续传递 SOC，禁止每日重置。
- 附件 3 的日期先向下填充，再按发布日期与预测步长对齐；光伏夜间零值不得作为缺失值填补。
- 主结果暂按模板列顺序映射；整体平移 10 分钟只作为敏感性实验，不能混入主结果。
- 任何预测只能使用决策时刻已经可见的信息。随机切分、当天真实未来值和未来实际价格不得进入可执行策略。

### 3. 模型共同口径

- 统一能量平衡、SOC 状态转移、容量上下限和充放电功率限制只实现一次，问题 1～4 共同调用。
- 主口径暂取充电效率与放电效率均为 0.9；“0.9 为总往返效率”单列为敏感性方案。
- 不允许向外网售电，允许弃光；充放电同时发生时先用极小吞吐量惩罚消除退化，仍无法消除再采用二元互斥变量。
- 问题 1 日初和日末 SOC 均为 6000 kWh；问题 2～4 连续传递 SOC，并显式处理最终日终端价值或约束。
- 预测与优化必须保留最简单 baseline，主模型不能只有复杂方案而没有可比较基准。
- 调整费用、多次调整基准和 10 分钟区间含义在最终口径确定前均保留可配置参数，不得写死在多个脚本中。

### 4. 文件和输出边界

| 内容 | 唯一位置 | 主写入者 |
| --- | --- | --- |
| 原始附件 | `data/raw/` | 全员只读 |
| 标准化数据 | `data/processed/` | 队员 B |
| 模型代码 | `src/` | 队员 A/B 按模块分界 |
| 可执行入口 | `scripts/` | 对应模块负责人 |
| 数值结果 | `results/` | 运行脚本生成 |
| 论文图片 | `figures/` | 队员 B 生成，队员 C 选用 |
| 假设与实验记录 | `docs/` | 任务负责人 |
| 论文材料 | `paper/` | 队员 C |

同一时段禁止两人修改同一文件。共享结果必须由脚本生成，文件名带问题号和方法名，例如 `q2_scenario_summary.csv`。聊天中的数字、截图和临时 Notebook 输出不算交付。

### 5. 复现与交付门槛

每项任务交付时必须同时给出：输入路径、运行命令、输出路径、关键参数、完成状态、验证结果和已知风险。核心结果至少通过下列一种验证：baseline 对比、边界检查、滚动回测、残差分析、敏感性分析或约束残差检查。

提交给队友前检查：

```powershell
uv sync --locked
uv pip check
uv run --locked python scripts/<对应脚本>.py
```

未经团队明确授权，不创建或切换分支、不 commit、不 push。获得分支授权后，每人只在自己的短生命周期分支工作，并按 `team/workflow.md` 交叉评审。

## 二、三人职责与接口

| 角色 | 主责 | 首要交付 | 向其他人提供 | 必须复核 |
| --- | --- | --- | --- | --- |
| 队员 A：建模与优化 | 统一物理模型、问题 1、问题 2～4 优化框架 | 可独立测试的能量流/SOC 内核和问题 1 结果 | 决策变量、约束、成本函数、求解接口 | B 的数据单位与预测输入；C 的公式表述 |
| 队员 B：数据与预测 | 附件读取、时间轴、动态数据审计、因果预测和情景 | 标准长表、数据字典、三类 baseline、预测残差 | 标准字段、训练/回测切分、残差情景 | A 的单位换算与输出；C 的图表数字 |
| 队员 C：论文与独立复核 | 假设、符号、论文章节、结果模板、独立核算 | 论文骨架、假设决策表、结果核验表 | 章节缺口、需补实验、格式和模板要求 | A/B 的公式、数字、图表与结论强度 |

固定接口：B 向 A 交付标准数据；A 向 B/C 交付模型输出；C 不直接改 A/B 的核心代码，而是提交核验问题和论文需求。任何接口变更必须在下一次同步点前通知全员。

## 六、同步时必须立即上报的问题

- 时间列、单位或 SOC 定义与共享口径不一致；
- 预测特征可能使用未来信息；
- 优化不可行、同时充放电、SOC 越界或跨日断裂；
- 结果无法由记录命令重现；
- 论文数字与结果文件不一致；
- 原始数据疑似被修改；
- 需要增删依赖、改变标准字段或改变输出模板。

发生阻塞时，负责人先保留失败日志、最小输入和运行命令，再在共享进度表标记为“阻塞”；不得用手工改结果、跳过日期或放宽物理约束掩盖问题。
